# Vesutil: собственная backend-инфраструктура

## Цель

Построить собственный серверный слой Vesutil без зависимости от Supabase:
- PostgreSQL — основная база данных;
- Next.js Route Handlers — HTTP API;
- серверный модуль `src/lib/db` — подключение к PostgreSQL;
- собственная авторизация и серверная проверка ролей — отдельный следующий этап;
- файловое хранилище — отдельный этап после выбора места хранения.

Это не попытка повторить весь Supabase. Реализуются только функции, необходимые продукту.

## Что добавлено

- `pg` и единый пул подключений PostgreSQL;
- `docker-compose.yml` для локального PostgreSQL 16;
- пример локальной переменной `DATABASE_URL`;
- миграционный запускатель с блокировкой, таблицей применённых миграций и SHA-256 проверкой;
- health endpoint показывает `database: not_configured`, если база ещё не подключена, либо проверяет соединение при наличии URL;
- локальный тестовый сценарий создания компании, филиала, материала и опубликованного предложения для проверки чтения каталога.

## Локальный запуск

Требуются Docker Desktop (или Docker Engine с Compose), Node.js 20.9+ и npm.

1. Запустить базу: `docker compose up -d postgres`.
2. Скопировать `.env.example` в `.env`.
3. Установить зависимости: `npm install`.
4. Применить миграции: `npm run db:migrate`.
5. Запустить сайт: `npm run dev`.

Миграционный скрипт и тестовый seed получают переменные окружения из текущего процесса PowerShell. Если `.env` не загружается автоматически, выполни перед командами:

```powershell
$env:DATABASE_URL = "postgresql://vesutil:vesutil_local_only@127.0.0.1:5432/vesutil"
$env:DATABASE_SSL = "false"
```

## Локальная проверка каталога

При запущенном локальном PostgreSQL и применённых миграциях:

```powershell
npm run db:seed:local-test
```

Скрипт создаёт одну явно обозначенную тестовую компанию, тестовый филиал и предложение по картону без цены. Он отказывается работать, если URL указывает не на базу `vesutil` на localhost. Запись не является реальным поставщиком или коммерческим предложением.

При запущенном Next.js в другом окне проверь:

```powershell
node -e "fetch('http://localhost:3000/api/catalog/offers?kind=material&category=paper-cardboard').then(r=>r.json()).then(x=>console.log(JSON.stringify(x,null,2)))"
```

В ответе ожидается одна тестовая запись с `demo: false`, названием с префиксом `ТЕСТОВОЕ ПРЕДЛОЖЕНИЕ` и ценой `По запросу`.

Удалить тестовую компанию вместе с её филиалом и предложениями:

```powershell
npm run db:cleanup:local-test
```

Команда удаления также защищена проверкой localhost и имени базы.

## Важные ограничения текущего этапа

- На production-базу миграции не запускались.
- DATABASE_URL в Railway не задан; никакая база не создавалась.
- Каталог продолжает отдавать явно помеченные демонстрационные записи, если база не подключена.
- Тестовый seed — только локальный инструмент проверки, не публичный API и не регистрация компании.
- Авторизация, сессии, восстановление пароля, RLS/изоляция компаний и файловое хранилище ещё не реализованы.
- Миграции следует проверить на чистой локальной базе. Изменения уже применённых миграций запрещены: создаётся новая миграция.
- Перед подключением production потребуется TLS-настройка, секреты, сетевые ограничения, резервное копирование, мониторинг и тесты восстановления.
